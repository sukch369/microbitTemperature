# 마이크로비트 온도 탐구실 — 학생용 Google Apps Script 조회 사이트 (v1.0)

기존 **교사용 GitHub Pages v1.2.1 + 기존 교사용 Apps Script 데이터 업로드 서버**를 건드리지 않고, 같은 구글 스프레드시트를 읽는 **별도의 학생용 조회 전용 Apps Script 프로젝트**입니다.

## 파일과 역할

- `Code.gs`: `Measurements` 시트 조회만 수행합니다. 데이터를 추가·수정·삭제하지 않습니다.
- `Index.html`: 실험 제목, 6모둠 현황, 선택 모둠 A/B 그래프 화면
- `Styles.html`: 반응형 디자인
- `Script.html`: 20초 자동 새로고침, 그래프 출력, 모둠 전환

## 1. 학생용 Apps Script 새 프로젝트 생성

1. 기존 구글 스프레드시트는 **그대로 유지**하세요. 데이터 시트 이름은 `Measurements`여야 합니다.
2. [script.google.com](https://script.google.com/)에서 **새 프로젝트**를 만듭니다. 예: `마이크로비트 온도 탐구실 - 학생용 조회`.
3. 기본 `Code.gs`를 이 파일의 `Code.gs`로 **전체 교체**합니다.
4. 프로젝트에서 **+ → HTML**로 다음 세 파일을 각각 새로 만듭니다: `Index`, `Styles`, `Script`. 각각 제공된 `.html` 파일 내용을 붙여넣습니다.
5. `Code.gs`의 다음 값을 **기존 측정 데이터가 기록되는 스프레드시트 ID**로 수정합니다.

   ```javascript
   const VIEWER_SPREADSHEET_ID = '스프레드시트_실제_ID';
   ```

   예: `https://docs.google.com/spreadsheets/d/여기가ID/edit`에서 `/d/`와 `/edit` 사이의 부분입니다. **교사용 GitHub `config.js`에 있는 Apps Script URL을 여기에 넣지 마세요.**

6. Apps Script에서 `checkViewerSetup()`을 선택해 실행한 후 Google 접근 권한을 승인합니다. 실행 로그에서 `읽기 전용 연결 성공`을 확인하세요.

## 2. 학생용 웹 앱 별도 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포 → 유형 선택: 웹 앱**.
2. **다음 사용자 인증 정보로 실행: 나** (데이터 소유 교사 계정).
3. **액세스 권한: 모든 사용자** (로그인 없이 공유하려면; 조직 정책이 허용해야 함).
4. 배포 후 나온 `/exec`로 끝나는 학생용 **웹 앱 URL**을 복사합니다.
5. 향후 소스를 수정했다면 **배포 → 배포 관리 → 해당 배포 수정 → 새 버전 배포**를 해야 반영됩니다.

학생에게 직접 스프레드시트 편집 권한을 줄 필요는 없습니다. 학생용 웹 앱이 배포 교사 권한으로 **조회만** 수행합니다.

## 3. 실험별 링크 만들기

교사용 GitHub Pages의 하단 `데이터 관리 및 실험 설정`에서 원하는 실험을 선택하고 **실험 ID 복사**를 누릅니다. 전체 UUID가 클립보드에 복사됩니다.

학생에게 배포할 링크:

```text
https://script.google.com/macros/s/학생용배포ID/exec?session=교사용에서_복사한_실험ID
```

예: (형식 예시일 뿐, 실제 링크는 아닙니다)

```text
https://script.google.com/macros/s/AKfycb.../exec?session=11111111-2222-4333-8444-555555555555
```

특정 모둠으로 처음 열려면 맨 뒤에 `&group=4`를 추가할 수 있습니다. 해당 실험을 볼 학생에게만 링크를 전달하세요.

**실험 선택 목록을 제공하지 않으므로 학생은 링크에 적힌 실험만 기본 화면에서 조회합니다.** 단, 링크를 받은 사람이 다른 실험 ID도 알고 있다면 그 ID로 요청할 수 있습니다. 이는 로그인 기반 사용자별 접근 통제가 아닙니다. 공개 링크는 외부로 재전달될 수 있습니다.

## 4. 학생용 화면

- 실험 이름 / 위치 / 마지막 측정 시간
- 1~6모둠 각각 A/B 최신 온도. 모둠 카드를 눌러 그래프 전환
- 선택한 모둠의 측정 시작부터 마지막 시각까지 온도 그래프
- 온도 숫자·Y축 **정수 표시**
- 측정 공백(35초 초과)은 **점선**으로 실측 점 두 개를 연결. 없는 측정값을 보간해 저장하지 않음
- A와 B가 같을 때 **시각적으로 약 5px 분리** (실제 온도 값은 변경 없음)
- **20초마다** Sheets 새 기록 확인. 다만 교사측 약 30초 단위 동기화가 먼저 완료되어야 반영됨
- 실험 ID/USB 시리얼 연결/스프레드시트 쓰기·수정·삭제 버튼 없음

조회는 기존 구글 시트의 전체 행을 최대 1200개씩 나눠 읽어, 화면에서는 선택 실험 데이터만 누적합니다. **최근 350건·12,000행 제한은 이 별도 학생용 사이트에는 없습니다.** 다만 다른 실험의 데이터가 방대하거나 동시 접속자가 매우 많으면 초기 조회가 느려질 수 있습니다. 구글 Apps Script 실행 제한도 적용됩니다.

## 5. 검사 순서

1. 기존 교사용 GitHub Pages에서 마이크로비트 데이터 수집 및 시트 동기화가 되는지 확인합니다.
2. `Measurements` 시트의 `session_id`, `device_id`, `temperature_c`, `measured_at` 열에 실제 데이터가 있는지 확인합니다.
3. 학생용 웹 앱에 `?session=실험 UUID`를 붙여 접속합니다.
4. 6모둠 최신 온도가 보이는지, A/B 그래프가 모둠별로 바뀌는지 확인합니다.
5. 학생용 웹 앱만 열어 USB 연결이나 데이터 추가/삭제 기능이 없는지 확인합니다.
6. 교사용 새 데이터 업로드 이후 최대 약 20초 + 서버/동기화 지연 내에 반영되는지 확인합니다.

## 6. 권한과 보안 유의점

- `VIEWER_SPREADSHEET_ID`는 Apps Script 서버 코드에만 있고 학생 브라우저로 전달하지 않습니다. 시트 자체를 공개하지 않아도 웹 앱을 통해 조회할 수 있습니다.
- 학생용 새 프로젝트에는 **`doPost()`나 `setValues()` 같은 쓰기 기능이 없습니다.** 조회 사이트만으로 기존 데이터 저장 기능이 생기지 않습니다.
- 그러나 **기존 교사용 Apps Script의 공개 `doPost` 업로드 엔드포인트는 그대로 공개 상태**라면, 쓰기 요청을 별도로 검증하지 않는 한 외부 호출 위험이 남습니다. 이는 이번 학생용 사이트 분리만으로 해결되지 않습니다. 추후 교사 전용 업로드 인증을 추가할 것을 권장합니다.
- GitHub Pages 자체도 공개 사이트라면 교사용 페이지 주소를 아는 사람의 페이지 접속까지 기술적으로 차단한 것은 아닙니다.
- 실험명/반 이름 등에 개인정보를 넣지 않고 학생 이름·연락처 등 민감한 정보를 측정 기록에 저장하지 마세요.

## 고장 진단

- `실험 ID 없음`: 학생이 `?session=...` 없는 주소로 접속한 경우입니다.
- `데이터가 아직 없습니다`: 교사용 실험 ID와 시트의 `session_id`가 일치하는지, 동기화가 완료되었는지 확인하세요.
- `조회 실패: VIEWER_SPREADSHEET_ID...`: 학생용 `Code.gs`의 시트 ID가 설정되지 않았습니다.
- `Measurements 시트를 찾지 못했습니다`: 잘못된 스프레드시트 ID 또는 시트 이름을 확인하세요.
- `열 구성이 ... 다릅니다`: 1행의 헤더가 원래 교사용 `Code.gs`의 12개 헤더와 같은지 확인하세요.
- `권한 부족`: `checkViewerSetup()`을 교사 계정으로 실행하여 승인하고, 웹 앱을 **나로 실행**으로 배포하세요.
- 수정 후 화면이 그대로: 배포 관리에서 **새 버전**을 배포하세요.
